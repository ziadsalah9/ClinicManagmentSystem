--------------------------------------------------------------------------------
1. WHAT IT DOES
--------------------------------------------------------------------------------
The Scheduling module manages doctor-clinic shifts, weekly working rules, breaks,
exceptions and generated appointment sessions. Booking owns booking_session, so
Scheduling never writes Booking tables directly. Scheduling calls BookingFacade to
reconcile sessions while preserving booked appointments.

The generation horizon is 60 clinic-local dates: today plus the next 59 days.
Session generation is idempotent. A scheduled job reconciles every active
doctor-clinic association using a PostgreSQL advisory lock per doctorClinicId.

--------------------------------------------------------------------------------
2. SECURITY AND SCOPE
--------------------------------------------------------------------------------
Permission: SCHEDULE_MANAGE
Access: clinic OWNER/ADMIN managers, or the DOCTOR who owns the doctorClinic
association. Actor IDs are never accepted from request bodies.

Base path:
/api/v1/clinics/{clinicId}/doctors/{doctorClinicId}/schedule

{clinicId} is the clinic UUID. {doctorClinicId} is the doctor-clinic association
UUID, not the doctor UUID. Get it from:
GET /api/v1/clinics/{clinicId}/doctors
The Hoppscotch request "Get all doctors in clinic" stores it as doctorClinicId.

4. ENDPOINTS
--------------------------------------------------------------------------------
GET /shifts
  List shifts for the doctor-clinic association.

POST /shifts
  Create a shift.
  Body:
  {
    "name": "Morning clinic",
    "capacityMode": "CALCULATED",
    "averageVisitMinutes": 15,
    "fixedCapacity": null,
    "effectiveFrom": "2026-11-11",
    "expectedVersion": null,
    "weeklyRules": [
      {
        "dayOfWeek": "SUNDAY",
        "startTime": "09:00",
        "endTime": "14:00",
        "followUpQuota": 2,
        "breaks": [
          { "startTime": "11:00", "endTime": "11:15" }
        ]
      }
    ]
  }
  capacityMode: CALCULATED or FIXED.
  averageVisitMinutes: 3..60 (required for CALCULATED).
  fixedCapacity: >= 1 (required for FIXED).
  weeklyRules must be non-empty. Rules for the same day must not overlap.
  Returns 201 with ShiftView.

PUT /shifts/{shiftId}
  Update a shift using the same body as POST. expectedVersion is optional but
  recommended. An update that would invalidate existing bookings returns
  409 BOOKING_CONFLICT.

PATCH /shifts/{shiftId}/activation
  Body: { "active": true, "expectedVersion": 0 }
  expectedVersion is required by validation. Deactivation stops future generation
  but does not delete existing sessions and does not reconcile them.

POST /previews/capacity
  Body: same ShiftRequest shape. Returns CapacityPreviewView:
  { from, to, sessions: [{date, startTime, endTime, capacity, followUpQuota}] }
  Read-only; no persistence.

POST /shifts/{shiftId}/previews/change
  Body: same ShiftRequest shape. Returns ChangePreviewView:
  { affectedSessions: [...], hasBlockingChanges, conflicts: [...] }
  Read-only; reports booking conflicts before applying an update.

GET /exceptions
  List active and cancelled exceptions.

POST /exceptions
  Body:
  {
    "shiftId": null,
    "type": "DAY_OFF",
    "dateFrom": "2026-11-15",
    "dateTo": "2026-11-15",
    "startTime": null,
    "endTime": null,
    "reason": "Public holiday"
  }
  type: DAY_OFF or CHANGED_HOURS.
  dateFrom and dateTo are required. shiftId null applies to all shifts.
  DAY_OFF must omit startTime/endTime. CHANGED_HOURS requires both and replaces
  the normal shift hours for the date range. Returns ExceptionView.

DELETE /exceptions/{exceptionId}
  Cancel an exception. Body: { "expectedVersion": 0 }
  Sets cancelledAt; affected sessions are reconciled within the horizon.

POST /sessions/generate
  Idempotent reconciliation. Returns SessionGenerationView:
  { from, to, sessions: [...], conflictingSessionIds: [...] }
  Existing booked sessions are preserved.

GET /sessions?from=2026-11-11&to=2027-01-09
  List generated sessions in a clinic-local date range. Both parameters are
  required. Returns a list of SessionView.

6. ERRORS
--------------------------------------------------------------------------------
400 INVALID_INPUT / INVALID_DATE_RANGE / VALIDATION_FAILED /
    INVALID_REQUEST_BODY / INVALID_PARAMETER / MISSING_PARAMETER
403 ACCESS_DENIED or PASSWORD_CHANGE_REQUIRED
404 DOCTOR_CLINIC_NOT_FOUND / SHIFT_NOT_FOUND / EXCEPTION_NOT_FOUND
409 STALE_VERSION / SHIFT_NAME_CONFLICT / SHIFT_CONFLICT / BOOKING_CONFLICT /
    CONCURRENT_MODIFICATION / SCHEDULE_DATA_CONFLICT

All responses are RFC 7807 ProblemDetail with title, detail, code and retryable.
Validation responses include an errors array with field/message entries. Invalid
enum values report the allowed values (for example DAY_OFF, CHANGED_HOURS).

Optimistic locking is used for shift, exception and session updates. Never ignore
409 STALE_VERSION; reload the resource and retry with the current version.
